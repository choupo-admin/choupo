# A NonCommercial compilation in the public tree

*Recorded 2026-09-01.  Nothing here changes a value, and nothing here deletes
a record.  What changed is that the licence gate can now see a source it had
never heard of, and that 36 records are visibly pinned instead of invisibly
tolerated.*

## How it was found

The next tutorial needs sulfur vapour — S6 and S8 — because the Claus furnace
cannot be written down without them: which allotrope dominates is itself an
equilibrium.  Neither is in the catalogue, so the question was where to get
them from cleanly.  `S2.dat` and `S.dat` are in the catalogue, so the obvious
answer was "the same place those came from", and their banner says:

    Generated by bin/import_nasa.py from NASA-7 polynomial data
    (BURCAT.THR).

One directory away, `bin/curate/import_gibbs_nasa.py` says, in capitals:

    * BURCAT (Third Millennium DB) is the convenient single NASA-7 file w/ CAS +
      S298 + Cp + ATcT updates -- and is licence-EXCLUDED (verbatim NonCommercial +
      no-redistribution terms).  Every package that bundles it (thermochem/RMG/
      thermopy) is PROVENANCE LAUNDERING.  *** DO NOT RETRY Burcat via ANY route. ***

And `bin/curate/check_source_licence.py` — the gate whose entire job is to keep
encumbered sources out of shipped values — had never heard the name.

**One decision, three homes: a tool that forbids it, a tool that performs it,
and a gate that does not know it exists.**  The forbidding and the performing
never met, so the exclusion was a sentence in a comment and the import was a
fact in the tree.

## What the licence actually says

Read at the distribution site rather than remembered: the database is

> "provided free of charge for non commercial use, on condition that proper
> quotation will be included in the pertinent publications."

NonCommercial.  `CLAUDE.md` §10 excludes that **regardless of copyleft**, and
not because there is a licence to honour — because the restriction is against
the project's own free-for-commercial ethos.  The curation protocol's phrasing
for this class is *"do not enter their numbers, even cited"*.

## Why the rule is not the aggregator rule

The gate already had a careful rule for NIST/CRC/DIPPR: an encumbered name may
appear **after a route marker** (`via`, `through`), because a primary read
*through* an aggregator came from the journal and the aggregator is only where
somebody looked.  That distinction saved two innocent records when the gate was
written.

It does not transfer.  For a NonCommercial **compilation** the arrangement IS
what would be copied, so `via Burcat` is not a defence — it is a confession.
The new rule therefore has no `via` branch.  What it does allow is the name
after a **cross-check** marker: a record that computes its value elsewhere and
compares it against Burcat enters no Burcat number.  Exactly one record in the
tree does that (`OH.dat`, "cross-checked with Burcat's thermodynamic database"),
and it is the negative that proves the allow-branch is not permanently true.

Sabotage S2 is the one worth knowing: an implementation written by analogy to
the aggregator rule would have let `via Burcat` pass, and would have been green.

## What was found, counted rather than remembered

36 records in `data/standards`, in two classes the gate deliberately does not
merge:

* **26 name `BURCAT.THR`** (or a "card" hand-selected from it).  The value was
  read out of the licensed file.  No ambiguity.
* **10 name "Burcat 2005 / JANAF"** — the *publication*.  These are the
  `NASA7_INLINE` set embedded in `bin/import_nasa.py`, transcribed by hand into
  the tool.  Whether a citation of the published report is a citable paper or
  the database under another name is a legal reading, and **both answers are
  defensible**.

## What was deliberately NOT done

* **Nothing was deleted.**  The 36 are the entire radical / sulfur / chlorine
  pool that six Gibbs tutorials are built on.  Removing them to close a licence
  gap, on my own reading of a one-sentence licence, would break the corpus to
  settle a question that is not mine.
* **No replacement number was written.**  A substitute datum needs a primary in
  hand.  Inventing one converts *encumbered* into *falsely sourced*, and the
  second is undetectable by any reader or tool.
* **The publication-vs-file question is reserved for Vítor.**  A gate that
  pinned 26 and stayed silent about the other 10 would tell the next reader the
  10 are clean, so both classes are pinned and the registry entry states which
  is which and why.

## The remedy, which the tree already names

`bin/curate/import_gibbs_nasa.py` establishes the clean routes: **NASA TM-4513**
(McBride, Gordon & Reno 1993 — a US government work, public domain) for
`dHf_298`/`s_298`/Cp, and **ATcT** (DOE, versioned OSTI DOI, no NC clause) for
`dHf`.  Re-importing a species from there discharges its pin, one at a time,
with no ruling required.

That is also the route S6 and S8 must take when the sulfur tutorial needs them.
The finding did not block the tutorial; it decided where its data comes from.

## A smaller thing that rode along

`gate_manifest.py` captures only the **first line** a gate prints as its claim,
so a claim printed on a second line is invisible in the one artefact that
answers *"what does this project check?"*.  The NonCommercial clause was moved
into the first line, and the caveat — which is not a claim — stayed on the
second.

And the manifest gained `--only <gate>`: it still DERIVES a claim by running
the gate, it just runs the ones that changed.  Full regeneration costs an hour
(several gates build the engine), which in practice means a changed OK line
does not get re-observed and the manifest drifts.  Each entry is independent
and the file carries no global timestamp, so a merged entry asserts nothing
about the others — and the arm refuses on failure or timeout exactly as the
full one does, because a failure is the absence of a claim, not a claim.
